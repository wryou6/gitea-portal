# Feature Specification: 設定頁重設計與遷移功能退役

**Feature Branch**: `main`

**Created**: 2026-10-03

**Status**: Draft

**Input**: User description: 重新設計設定頁面，修正切換配色時其他配色預覽也跟著變動、導致只能預覽一種色卡的問題；改善介面語言切換後的排版；移除已過時的標籤遷移功能；新增三種以深色外觀為優先的配色。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 清楚瀏覽與調整個人設定 (Priority: P1)

Portal 工程師可以在設定頁快速辨認並調整外觀模式、配色及介面語言。各設定分組清楚，選項文字在繁體中文、英文及日文下都保持易讀，選擇後立即反映在介面。

**Why this priority**: 設定頁是外觀與語言偏好的唯一入口；清晰層級及可讀排版直接影響完成設定的效率。

**Independent Test**: 使用三種介面語言分別瀏覽設定頁，調整外觀模式、配色及語言，確認選擇可辨識、立即生效且版面保持可讀。

**Acceptance Scenarios**:

1. **Given** 使用者開啟設定頁，**When** 檢視可用偏好，**Then** 外觀模式、配色及介面語言各自位於有清楚標題與說明的區塊。
2. **Given** 使用者開啟設定頁，**When** 瀏覽偏好區塊，**Then** 介面語言位於最上方，外觀模式其次，配色最後。
3. **Given** 使用者切換繁體中文、英文或日文，**When** 設定頁完成更新，**Then** 區塊標題、選項與說明保持完整可讀，且不與控制項重疊或遭裁切。
4. **Given** 使用者選擇外觀模式、配色或介面語言，**When** 作出選擇，**Then** 對應偏好立即套用並以清楚狀態指出目前選項。
5. **Given** 使用者以鍵盤操作設定頁，**When** 移動焦點並選擇各項偏好，**Then** 所有選項均可到達、操作且能辨認焦點和選取狀態。

### User Story 2 - 比較各配色預覽 (Priority: P1)

工程師可以在選擇前同時辨認六個配色方案的視覺差異，不會因目前套用的配色改變而讓其他色卡預覽一起變色；三款新增方案以深色外觀為主要設計情境，同時提供協調可讀的淺色外觀。

**Why this priority**: 配色比較是選擇偏好的必要依據；互相污染的預覽會讓使用者無法判斷選項差異。

**Independent Test**: 逐一選擇六個配色，確認所有色卡的預覽外觀維持各自方案；切換深色外觀比較新增三款的表面層次、強調色及狀態色，再切回淺色確認仍清晰可讀。

**Acceptance Scenarios**:

1. **Given** 設定頁列出多個配色，**When** 使用者檢視或切換選項，**Then** 每張色卡始終呈現該方案專屬的預覽。
2. **Given** 使用者已選取一個配色，**When** 切換至另一配色，**Then** 實際介面套用新配色，其他色卡仍呈現其各自預覽。
3. **Given** 使用者重新載入設定頁，**When** 讀取已保存偏好，**Then** 目前配色選取正確，所有配色預覽仍可同時辨認。
4. **Given** 使用者使用深色外觀，**When** 比較三款新增配色，**Then** Carbon、Ember、Glacier 各自呈現清楚不同的深色表面與強調色，文字及狀態資訊保持可讀；在淺色外觀下三款仍可正常閱讀。
5. **Given** 使用者比較任一配色，**When** 檢視色卡預覽，**Then** 預覽以該配色實際使用的文字、表面、強調色和 Status badge 呈現，不以獨立色票取代元件外觀。
6. **Given** Issue 含有自訂顏色的 Gitea Label，**When** 使用者切換淺色或深色外觀，**Then** Label 保留其色彩辨識並適應目前表面，名稱保持清楚可讀，且 Gitea 原始資料不變。
7. **Given** 使用者瀏覽深色外觀下的 Issue，**When** 比較 Issue 識別碼與次要資訊，**Then** 識別碼和主要內容易於辨認，次要中繼資訊仍維持較低視覺層級。

### User Story 3 - 不再提供過時的標籤遷移 (Priority: P1)

維護者及工程師不再看到或操作已不需要的標籤遷移工具；Portal 後續狀態辨識只依目前採用的 Status 標籤語意。

**Why this priority**: 過時的遷移入口可能導致不必要的批次 Gitea 資料變更，也會讓設定頁持續暴露已退役的功能。

**Independent Test**: 檢視設定頁及可用管理操作，確認不再有遷移入口；使用只含目前格式 Status 標籤的 Issue 驗證 Status 顯示及操作仍正常。

**Acceptance Scenarios**:

1. **Given** 任一使用者檢視設定頁，**When** 瀏覽所有設定區塊，**Then** 不會看到或啟動標籤遷移功能。
2. **Given** Portal 顯示或更新 Issue Status，**When** 讀取其 Labels，**Then** 只依目前格式的 Status 標籤辨識狀態及轉換原因。
3. **Given** Issue 僅有舊格式的工作流程標籤，**When** Portal 呈現該 Issue，**Then** 不將舊標籤轉換或推斷為目前 Status；舊標籤本身仍由 Gitea 保留。

### Edge Cases

- 窄視窗或較長的語言文字不得遮蓋選取控制、造成橫向溢出或令焦點不可見。
- 外觀偏好與介面語言偏好已保存時，重新載入仍須呈現正確選項；缺少或無效的偏好須回復既有預設值。
- 未登入使用者仍可載入設定頁的非帳號專屬介面；不新增伺服器端個人設定保存。
- 舊格式工作流程標籤不得被遷移、刪除或用來推斷目前狀態。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 設定頁 MUST 將介面語言、外觀模式及配色組織為可清楚辨認的設定區塊，且依此順序由上至下排列；每區有明確標題。
- **FR-002**: 所有設定文字 MUST 支援繁體中文、英文及日文；介面語言切換後，各區塊標題、選項與說明 MUST 保持可讀且不得與控制項重疊或裁切。
- **FR-003**: 外觀模式、配色及介面語言 MUST 保留現有選擇、即時套用及本機偏好保存行為。
- **FR-004**: 設定頁 MUST 同時展示六個配色各自固定的預覽；切換目前配色 MUST NOT 改變其他配色預覽的顏色。
- **FR-005**: 設定頁各偏好選項 MUST 以文字及可辨識的選取狀態傳達其名稱與目前選擇，並可使用鍵盤操作。
- **FR-006**: Portal MUST 停止提供標籤遷移入口及遷移操作；不得再有能觸發遷移批次修改的使用者功能。
- **FR-007**: Portal MUST 只以目前格式的 Status 標籤辨識 Status 與狀態轉換原因；舊格式工作流程標籤 MUST NOT 再作相容辨識或轉換依據。
- **FR-008**: Portal MUST NOT 因退役遷移功能而刪除或修改 Gitea 上的舊格式 Labels；此功能退役不執行 Issue 資料遷移。
- **FR-009**: 設定頁及標籤相容功能調整 MUST NOT 改變登入狀態、外觀/語言偏好持久化範圍、或其他 Gitea Issue 資料。
- **FR-010**: Portal MUST 新增 Carbon、Ember、Glacier 三種配色。三者 MUST 以深色外觀為主要設計情境，維持足夠的文字與狀態對比，並提供可讀的淺色外觀配對；既有三種配色及偏好保存行為 MUST 維持。
- **FR-011**: 每個配色色卡 MUST 顯示該配色的表面、主要文字、強調色及 Status 樣式；樣本外觀 MUST 與實際介面一致，且不得受目前選取配色影響。
- **FR-012**: Gitea Label MUST 保留其既有色彩辨識，並配合淺色或深色外觀維持文字清晰；顏色不得作為唯一辨識方式，且此呈現調整 MUST NOT 改變 Gitea Label 資料。
- **FR-013**: 深色外觀下，Issue 識別碼及主要內容 MUST 清楚易辨並與次要資訊形成層級；一般文字對比至少符合 WCAG 2.2 AA 4.5:1，狀態亦以文字語意共同辨識。

### Key Entities _(include if data involved)_

- **外觀偏好**：使用者選擇的 Light、Dark、System 顯示模式，以及目前配色方案。
- **介面語言偏好**：使用者選擇的繁體中文、英文或日文顯示語言。
- **Status 標籤**：Gitea Issue 上表示目前工作狀態及轉換原因的 Labels；Portal 只辨識目前採用的標籤格式。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 使用者在設定頁能同時辨認 100% 的可用配色預覽，切換任一配色後未選項預覽仍保持原有外觀。
- **SC-002**: 繁體中文、英文及日文三種介面下，所有設定標題、選項與說明均完整可讀；在 375px、768px、1024px 及 1440px 視窗寬度均無重疊或橫向溢出。
- **SC-003**: 使用者可在兩次操作內抵達並調整任一設定類別，且目前值清楚可辨。
- **SC-004**: 設定頁中可觸發標籤遷移的入口數量為零；舊格式 Labels 不會被此功能修改或刪除。
- **SC-005**: 移除舊標籤相容辨識後，使用目前格式 Status Labels 的 Issue 仍能在所有工作檢視正確呈現與轉換狀態。
- **SC-006**: 六個配色均可被選取、保存及載入；三款新增配色在深色模式有可辨認的差異，且各自淺色模式下文字和狀態標籤保持可讀。
- **SC-007**: 六款預覽均實際呈現表面、主要文字、強調色和三種 Status badge；切換配色後，未選色卡的顏色及元件呈現不變。
- **SC-008**: Gitea Label 的色彩會反映在淡色底與邊框，文字仍與淺/深主題表面保持至少 4.5:1 對比；深色下 Issue 識別碼與主要內容對背景至少 4.5:1。

## Assumptions

- 現有 Light、Dark、System、配色及介面語言選項和各帳號本機保存方式維持不變；本功能重整其呈現與互動清晰度。
- 新增配色名稱固定為 Carbon、Ember、Glacier；使用既有 per-login 本機偏好格式保存其選取值，不增加 API 或伺服器端偏好。
- 標籤遷移功能已不再需要；舊格式 Labels 即使仍存在，也不由本功能執行遷移、刪除或 Status 相容推斷。
- 本功能只退役 Portal 的遷移及舊格式辨識能力，不改動 Gitea Issue、Labels 或其他伺服器端資料。
- 所有支援的裝置尺寸均以可用的響應式 Web 介面為目標。
