## User Scenarios & Testing

### User Story 1 - 快速篩選未完成工作 (Priority: P1)

工程師可用「未完成」快速選取 Todo 與 In Progress，並看到兩個狀態選項同步反映選取。工程師也可個別取消其中一個狀態，讓結果只符合剩餘選取的狀態。

**Why this priority**: 這是快速查看待辦與處理中工作的主要需求，並保留逐一調整結果的能力。

**Independent Test**: 在任一工作檢視點選「未完成」，確認 Todo 與 In Progress 被選取且 Done 不被選取；取消 In Progress，確認結果只包含 Todo。

**Acceptance Scenarios**:

1. **Given** 狀態篩選未選取任何特定狀態，**When** 工程師點選「未完成」，**Then** Todo 與 In Progress 被選取，Done 未被選取，且結果只包含前兩種狀態。
2. **Given** Done 已選取或全部狀態未篩選，**When** 工程師點選「未完成」，**Then** 選取狀態直接變成 Todo 與 In Progress。
3. **Given** Todo 與 In Progress 均已選取，**When** 工程師取消 In Progress，**Then** 只保留 Todo 篩選，且結果立即更新。
4. **Given** 狀態選取已被個別調整，**When** 工程師再次點選「未完成」，**Then** 狀態選取重設為 Todo 與 In Progress。

---

### User Story 2 - 複選狀態、優先級與類型 (Priority: P1)

工程師可在共用篩選面板中選取多個狀態、優先級或類型，使用者不需逐一切換單一條件即可找到符合的工作。

**Why this priority**: 多值篩選可表達常見工作集合，同時維持三種檢視一致的結果。

**Independent Test**: 同時選取多個優先級及類型，確認同一類別任一選項符合即可；再加入狀態條件，確認結果同時符合各類別。

**Acceptance Scenarios**:

1. **Given** 工程師選取多個狀態，**When** 查看結果，**Then** 結果包含任一已選狀態的工作。
2. **Given** 工程師選取多個優先級或多個類型，**When** 查看結果，**Then** 各類別內符合任一已選值的工作均可顯示。
3. **Given** 工程師選取狀態、優先級、類型及負責人條件，**When** 查看結果，**Then** 每筆工作都符合每個已設定類別中的條件。
4. **Given** 工程師取消某個已選 Badge，**When** 查看結果，**Then** 只移除該選項，其餘選取仍生效；某類別沒有選取值時，該類別不限制結果。

---

### User Story 3 - 跨工作檢視還原多選條件 (Priority: P2)

工程師可在 List、Kanban 與 Gantt 間切換或重新開啟已保存的網址，並還原同一組多選篩選。

**Why this priority**: 共用工作範圍必須在檢視切換與分享網址後保持一致。

**Independent Test**: 設定多個狀態、優先級與類型，切換三種檢視並重新載入網址，確認條件與結果一致。

**Acceptance Scenarios**:

1. **Given** 工程師已設定多個篩選值，**When** 切換 List、Kanban 或 Gantt，**Then** 各檢視保留相同條件並顯示符合結果。
2. **Given** 網址包含有效的多選條件，**When** 工程師重新開啟或重新載入該網址，**Then** 篩選條件與結果可還原。
3. **Given** 網址包含部分無效選項及有效選項，**When** 工作檢視載入，**Then** 無效選項不套用，其他有效條件仍正常生效。
4. **Given** 工程師已連續變更篩選條件，**When** 使用瀏覽器上一頁或下一頁，**Then** 每次操作都還原該歷史項目的網址、選取狀態與結果。

### Edge Cases

- 某一類別所有選項都取消時，該類別不限制結果，不應產生零結果。
- 篩選條件組合沒有符合項目時，顯示正常的無結果狀態，不得呈現為載入錯誤。
- 狀態條件未設定時，保留目前對狀態異常工作項目的既有呈現方式；設定任一明確狀態後，異常狀態不符合選取條件。
- 更新篩選結果時，List 分頁及三種檢視的結果摘要需反映篩選後結果。
- 窄螢幕、鍵盤操作及支援語系下，所有篩選選項仍可辨識及操作。

## Requirements

### Functional Requirements

- **FR-001**: List、Kanban 與 Gantt MUST 共用相同的狀態、優先級、類型多選條件與結果語意。
- **FR-002**: 狀態篩選 MUST 提供「未完成」快捷選項；選取時 MUST 將狀態集合直接設為 Todo 與 In Progress，並清除 Done 與未篩選狀態。
- **FR-003**: Todo、In Progress、Done MUST 可個別選取及取消；「未完成」選項 MUST 在 Todo 與 In Progress 同時選取時呈現選取狀態。
- **FR-004**: 優先級及類型 MUST 支援選取多個既有值，且不得新增重複的篩選 Badge。
- **FR-005**: 同一篩選類別中，符合任一選取值的工作 MUST 通過該類別條件；不同已設定類別的條件 MUST 同時符合。
- **FR-006**: 工程師 MUST 能個別移除一項已選條件；移除某類別最後一項後，該類別 MUST 回到未篩選狀態。
- **FR-007**: 每次條件變更 MUST 立即更新 List、Kanban、Gantt 結果並建立一個瀏覽器歷史項目；重新載入、上一頁/下一頁及檢視切換 MUST 還原對應的有效條件與結果。
- **FR-008**: 無效或不支援的篩選值 MUST 不影響其他有效條件或使工作檢視失效。
- **FR-009**: 篩選 MUST 僅作用於目前工作區中使用者可讀取的 Gitea Issues，不得改寫 Issue 資料或繞過 Gitea 權限。
- **FR-010**: 新增或修改的可見標籤、提示與無障礙名稱 MUST 支援繁體中文、英文及日文。
- **FR-011**: 篩選控制 MUST 支援鍵盤操作、可見焦點及輔助科技可辨識的選取狀態；窄螢幕不得因此產生水平溢出。

### Key Entities

- **共用多選篩選**：套用於目前工作區及三種工作檢視的狀態、優先級、類型與既有其他篩選條件；各類別可包含零個或多個選取值。
- **未完成快捷選取**：狀態篩選中的便利選項，其選取結果固定為 Todo 與 In Progress；可再個別調整兩個狀態。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 使用者一次操作即可將狀態篩選設定為 Todo 與 In Progress，且 Done 不在該結果集合中。
- **SC-002**: 使用者可取消 In Progress 後，立即看到只符合 Todo 的結果。
- **SC-003**: 對同一組條件，List、Kanban 與 Gantt 顯示相同的符合工作集合。
- **SC-004**: 已設定的多選條件在檢視切換、網址重新開啟及瀏覽器返回/前進後均可完整還原。
- **SC-005**: 多選優先級、類型及狀態時，同類別符合任一值、跨類別同時符合的結果規則可由所有驗收情境確認。

## Assumptions

- 「未完成」是狀態篩選的快捷預設，不是額外的第四種 Issue Status，也不是獨立疊加的條件；再次點選會重設為 Todo 與 In Progress。
- 優先級與類型沿用既有選項及其資料定義；本功能只改變選取數量與篩選邏輯。
- 負責人條件維持既有單選及比對行為，並與多選類別條件共同套用。
- 現有 URL 還原與跨檢視共用條件行為延伸支援多選值。
