# Feature Specification: 重新登入提示版面修正

**Feature Branch**: `039-session-notice-layout`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: 修正重新登入後的提醒在各種工作 View 中破壞版面的問題。使用者選擇以不占用版面空間的浮動提示呈現，並可自行關閉。

## Clarifications

### Session 2026-10-07

- Q: 浮動提醒固定在哪裡，最不容易遮住各種 View 的主要內容或操作？ → A: 右下角，並保留視窗邊界留白。
- Q: 右下角浮動提醒顯示時，底下的工作內容可以被提醒覆蓋到什麼程度？ → A: 可覆蓋非操作內容，但底下的工作操作仍可點擊。

## User Scenarios & Testing

### User Story 1 - 重新登入後繼續檢視工作 (Priority: P1)

工程師在使用 Portal 時遇到登入狀態失效，完成重新登入並返回原工作頁後，需要知道登入已恢復、頁面資料應重新載入，以及未送出的 Issue 內容需要重新輸入；提醒不得改變工作 View 版面或阻擋主要操作。

**Why this priority**: 登入狀態失效可能發生在任一工作頁。恢復工作脈絡與保留 View 可用性是重新登入流程完成的必要條件。

**Independent Test**: 在登入後的工作頁模擬登入狀態失效，完成重新登入並返回原路徑，確認提醒可讀、工作 View 尺寸與捲動狀態不因提醒而改變，且可關閉。

**Acceptance Scenarios**:

1. **Given** 使用者在任一受保護工作頁的登入狀態失效，**When** 使用者完成重新登入並返回原工作頁，**Then** Portal 顯示已重新登入及未送出 Issue 內容未保存的提醒。
2. **Given** 提醒正在顯示，**When** 使用者檢視 Issues、Kanban、Gantt、Dashboard、Settings 或 Repository 工作頁，**Then** 提醒不改變頁面可用寬高、不造成內容裁切或額外捲動；提醒可覆蓋非操作內容，但底下的工作操作仍可點擊。
3. **Given** 提醒正在顯示，**When** 使用者透過滑鼠或鍵盤關閉提醒，**Then** 提醒消失，且目前 View 保持原狀。
4. **Given** 畫面寬度為 320px 以上或使用英文、日文介面，**When** 提醒顯示，**Then** 文字可換行且不造成水平溢出。

### Edge Cases

- 提醒文字較長或視窗較窄時，提醒須留在可視範圍內，文字能換行，關閉控制仍可操作。
- 使用者已關閉提醒後在單頁瀏覽期間切換其他工作 View，提醒不應重新出現或造成版面跳動。
- 提醒覆蓋區域中，除提醒本身及關閉控制外，指標操作須傳遞到底下的工作頁。
- 重新登入提示不代表失敗的 API 請求或 Issue 變更已自動重送；Portal 不得暗示資料已保存。

## Requirements

### Functional Requirements

- **FR-001**: 重新登入成功並返回原受保護路徑後，Portal MUST 顯示已恢復登入狀態及未送出 Issue 內容未保存的在地化提醒。
- **FR-002**: 提醒 MUST 固定在視窗右下方並保留邊界留白，以浮動方式呈現；不得占用或改變工作頁的內容版面尺寸或捲動範圍。提醒可覆蓋非操作內容，但面板以外的指標操作 MUST 傳遞到底下的工作頁。
- **FR-003**: 使用者 MUST 能以滑鼠及鍵盤關閉提醒；關閉後在目前單頁瀏覽期間切換工作頁時不得再次顯示。
- **FR-004**: 提醒文字 MUST 支援繁體中文、英文及日文，並能在窄螢幕換行而不造成水平溢出。
- **FR-005**: Portal MUST 保留原本的登入回跳路徑，且 MUST NOT 自動重送登入失效前的請求或 Issue 變更。
- **FR-006**: 提醒 MUST 使用可供輔助技術辨識的狀態通知語意，且關閉控制須有明確名稱。

### Key Entities

- **重新登入提醒**：短暫的使用者介面狀態，包含恢復登入與未保存內容訊息、顯示狀態及使用者關閉狀態；不保存 Issue 草稿或變更資料。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 在 Issues、Kanban、Gantt、Dashboard、Settings 與 Repository 工作頁中，顯示或關閉提醒前後，主要內容區域的可用寬度、高度及捲動範圍均不因提醒而改變；提醒外的底層工作操作仍可使用。
- **SC-002**: 在 320px 以上寬度及繁中、英文、日文介面中，提醒與關閉控制均完整可見，且頁面沒有由提醒造成的水平溢出。
- **SC-003**: 使用者可透過鍵盤到達並關閉提醒；輔助技術可辨識提醒內容及關閉控制。
- **SC-004**: 重新登入後原工作路徑仍可開啟；失效前未送出的 Issue 內容不會被宣稱已保存或自動重送。

## Assumptions

- 重新登入成功後，提醒保持顯示直到使用者主動關閉，不自動逾時消失。
- 提醒在窄螢幕時仍保留視窗邊界，並確保文字和關閉控制在可視範圍內。
- 本功能只調整登入成功後的提醒體驗，不改變登入逾期判定、OAuth 流程、回跳政策或 Issue 儲存行為。
- 使用者關閉後的狀態只需在目前單頁瀏覽期間維持，不需跨瀏覽器重新載入保存。
