# 工作檢視需求

## 共用工作區與篩選

- 提供 All repos 與可讀 Repository 的 Issues、Kanban、Gantt 檢視；跨 repo Issue 顯示 repo 身分。
- 篩選條件在工作檢視間保持一致，URL 保留可分享的工作檢視狀態；非法或過期參數回退到安全預設值，不破壞頁面導覽。
- Assignee 快速篩選支援目前使用者及未指派項目；多選與篩選隱藏項目的選取行為保持一致。
- Issue 列表以近期到期資訊和標題優先協助掃描，顯示狀態、類型、優先度、負責人、日期及完整 Labels；Done 項目可依使用者設定隱藏或顯示。

## Kanban

- 欄位對應固定的 Todo、In Progress、Done；卡片呈現足以辨識 Issue 的標題、編號、Repository、負責人、日期及非流程分類資訊。
- 卡片可隱藏 status/workflow Labels，但 Issue 詳情與列表保留完整 Labels。
- 拖曳或狀態操作必須以可驗證的 Gitea 原子 Label replacement 更新狀態，使用樂觀並行控制；失敗時保留並呈現 Gitea 真實狀態，不呈現未保存的樂觀結果。
- 修復缺少或衝突的 workflow 狀態時，清楚標示 repair annotation、錯誤及 anomaly 欄位；不得默默改變 Gitea 資料。
- 欄位可獨立垂直捲動，時間線或頁面容器不得搶走欄位內捲動；小螢幕仍可操作卡片及篩選。

## Gantt 與排程

- Gantt 依 Issue start/due date 顯示時間條；未排程項目仍能建立排程，日期異常與逾期狀態有明確區別。
- 日期編輯使用可理解的日期介面，不要求使用者輸入內部 Label 格式；更新跨欄位失敗時重新讀取並呈現 Gitea 實際值。
- 支援移動今日日期指示、拖曳排程日期及平移時間軸；時間軸操作不可意外建立或改寫排程。
- 逾期提示在列表、Kanban、Gantt 保持一致；完成或無 due date 的 Issue 不誤標逾期。

## 列表與詳情

- Issues 檢視支援搜尋、排序、篩選、分頁及多選；複製選取內容為含標題列的 TSV，匯出 CSV 涵蓋所有資料而非僅目前頁面。
- Issue 詳情可由工作檢視進入並回到原工作脈絡；完整顯示描述、留言、Labels、Assignee、Milestone、狀態與原始 Gitea 連結。
- 欄位 badge 編輯須寫回 Gitea，遵守權限、原子更新與並行衝突處理。

## 視覺與導覽

- 共享篩選列與工具列在各工作檢視一致；側邊導覽可收合，收合時圖示仍可辨識且標籤保留無障礙名稱。
- SPA 導覽避免整頁閃白，直接開啟、重新載入與瀏覽器返回均保留有效路由及查詢狀態。
- 工作檢視的日期、狀態、錯誤、載入、空資料及修復標記須清楚區分；避免日期格式暴露內部儲存方式。
