# Feature Specification: Hover 展開側欄與工作檢視排序

**Feature Branch**: `034-hover-expand-sidebar`

**Created**: 2026-10-03

**Status**: Draft

**Input**: User description: 將左側導覽中的工作檢視排序改為 Kanban、Gantt、List，並讓側欄固定收合，滑過時覆蓋主要內容展開，而不推動工作區控制面板。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 快速切換工作檢視 (Priority: P1)

工程師可從全站左側導覽依序找到 Kanban、Gantt、List，並切換至對應工作檢視。建立問題入口仍位於這三個工作檢視之前。

**Why this priority**: 調整常用工作檢視的排列，讓使用者依目前慣用次序快速切換，同時保留全域建立問題入口。

**Independent Test**: 在 List、Kanban、Gantt 與其他主要頁面檢查側欄順序，逐一開啟各檢視並確認目的頁及目前項目標示正確。

**Acceptance Scenarios**:

1. **Given** 使用者位於任一登入後頁面，**When** 查看左側導覽，**Then** 建立問題入口之後依序顯示 Kanban、Gantt、List。
2. **Given** 使用者位於任一工作檢視，**When** 切換到另一工作檢視，**Then** 開啟目標檢視並保留既有工作區與適用的網址狀態。
3. **Given** 使用者位於某個工作檢視，**When** 查看左側導覽，**Then** 目前檢視仍有明確的目前頁面標示。

### User Story 2 - 以窄側欄保留工作區空間 (Priority: P1)

工程師瀏覽 Portal 時，側欄預設收合為圖示列，讓主要工作內容及控制面板保有固定空間；需要查看標籤時，可將游標移入側欄暫時展開。

**Why this priority**: 側欄不必持續佔用寬度，同時仍能在需要時辨認各項入口。

**Independent Test**: 在一般頁面及工作檢視頁面移入與移出側欄，確認側欄分別展開及收合，且主要內容和控制面板位置不變。

**Acceptance Scenarios**:

1. **Given** 頁面完成載入且游標不在側欄，**When** 使用者查看左側導覽，**Then** 側欄只顯示圖示，且主要內容使用原有工作區寬度。
2. **Given** 側欄為收合狀態，**When** 游標移入側欄，**Then** 側欄顯示圖示與文字並覆蓋主要內容，不改變主要內容或控制面板的位置與寬度。
3. **Given** 側欄以滑鼠移入方式展開，**When** 游標離開側欄，**Then** 側欄收合回圖示列。
4. **Given** 使用者以鍵盤操作，**When** 焦點進入側欄，**Then** 側欄顯示圖示與文字；焦點離開側欄後，側欄回到收合狀態。

### User Story 3 - 在觸控與輔助科技環境操作側欄 (Priority: P2)

無滑鼠 hover 的使用者仍能操作側欄導覽，並能以鍵盤或輔助科技辨識收合圖示代表的入口。

**Why this priority**: 固定收合及 hover 展開不應阻斷觸控、鍵盤或螢幕閱讀器使用者前往頁面。

**Independent Test**: 在觸控裝置直接點擊各入口，並以鍵盤和螢幕閱讀器檢查項目名稱、焦點及目前頁面狀態。

**Acceptance Scenarios**:

1. **Given** 裝置沒有 hover 輸入能力，**When** 使用者點擊收合側欄中的入口圖示，**Then** Portal 正常前往該入口。
2. **Given** 側欄處於收合狀態，**When** 輔助科技讀取導覽，**Then** 每個圖示入口都有可辨識的名稱及正確的目前頁面狀態。
3. **Given** 使用者鍵盤焦點位於展開的側欄，**When** 側欄顯示標籤，**Then** 視覺展開不遮住目前焦點，且所有入口仍可操作。

### Edge Cases

- 長標籤或窄視窗下展開的側欄不得造成內容水平溢出，導覽項目仍需可操作。
- 在一般頁面及全高工作檢視版面中，展開側欄均須位於頂部導覽之下並覆蓋內容，不得被控制面板或主要內容裁切。
- 游標仍在側欄內或鍵盤焦點仍在側欄內時，側欄須維持展開，以免使用者操作途中標籤消失。
- 切換頁面或重新載入後，側欄仍以收合狀態開始；不保存手動展開偏好。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 所有登入後頁面的左側導覽 MUST 依序顯示建立問題、Kanban、Gantt、List 等現有項目；此處 List 指 Issues 工作檢視。
- **FR-002**: 各工作檢視入口 MUST 維持既有導覽目的地、工作區脈絡、目前頁面標示，以及來源與目的檢視所支援的網址狀態行為。
- **FR-003**: 側欄 MUST 在游標未懸停且鍵盤焦點不在其中時固定呈現收合圖示列；不得提供手動固定展開或收合控制。
- **FR-004**: 游標懸停於側欄或鍵盤焦點位於側欄內時，側欄 MUST 顯示圖示與文字；游標及焦點皆離開側欄後 MUST 回到收合狀態。
- **FR-005**: 側欄展開 MUST 覆蓋主要內容，且不得改變主要內容、工作檢視控制面板或時間軸的版面寬度與位置。
- **FR-006**: 收合圖示及導覽入口 MUST 保留可供輔助科技識別的名稱、鍵盤操作能力、可見焦點及目前頁面狀態。
- **FR-007**: 沒有 hover 能力的裝置 MUST 可直接操作收合圖示前往對應頁面，不得依賴先展開側欄。
- **FR-008**: 側欄展開或收合 MUST NOT 改變 Issue、工作區、篩選或檢視偏好資料；展開狀態不保存為使用者偏好。

### Key Entities *(include if data involved)*

- **側欄呈現狀態**：由游標懸停或鍵盤焦點位置決定的暫時收合／展開畫面狀態，不作持久保存。
- **工作檢視導覽項目**：建立問題、Kanban、Gantt、List 等具目的地、顯示名稱與目前頁面狀態的入口。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 所有登入後主要頁面的工作檢視入口順序均為 Kanban、Gantt、List，並位於建立問題入口之後。
- **SC-002**: 在所有驗收頁面中，游標與焦點離開側欄時 100% 顯示收合圖示列；游標或焦點進入時 100% 顯示圖示與文字。
- **SC-003**: 在所有驗收頁面展開側欄時，主要內容及工作檢視控制面板的版面位置與寬度保持不變。
- **SC-004**: 所有側欄入口均可透過滑鼠或鍵盤啟動；在無 hover 裝置上均可直接點擊啟動。
- **SC-005**: 螢幕閱讀器可辨識每個收合入口的名稱及目前頁面狀態，且鍵盤焦點始終可見。

## Assumptions

- 「List」是現有 Issues 工作檢視；使用者要求的是將三種工作檢視排序為 Kanban、Gantt、List，建立問題仍排在前面。
- 展開採暫時性 hover 與 focus-within 行為；觸控裝置維持收合並可直接點圖示，不增加點擊切換或固定展開模式。
- 側欄覆蓋主要內容時仍置於頂部導覽列下方，展開狀態不寫入 session 或使用者偏好。
- 工作檢視導覽沿用 Feature 030、031 的 URL 狀態保留規則，不重新定義排序、篩選或返回語意。
