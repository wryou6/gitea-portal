# Feature Specification: 工作檢視篩選列版面

**Feature Branch**: `035-work-view-filter-layout`

**Created**: 2026-10-04

**Status**: Draft

**Input**: User description: 「列表、看板、甘特三個頁面的負責人、狀態、優先級、類型都放在主要版面上方同一行，依序排列；使用淡淡分隔與間距，不加大型底層面板以免浪費空間。」

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 從主要內容上方篩選工作 (Priority: P1)

工程師在列表、看板或甘特頁面時，可以直接在主要內容上方找到優先級、類型、狀態與負責人篩選器，不必在側邊控制區尋找這些常用條件。

**Why this priority**: 這些常用條件移至主要內容上方可簡化掃視路徑，並釋放主要工作檢視的橫向空間。

**Independent Test**: 分別開啟列表、看板及甘特頁，確認三頁均在主要內容上方顯示相同的篩選列排列，並能套用各篩選條件更新結果。

**Acceptance Scenarios**:

1. **Given** 工程師位於桌面版列表、看板或甘特頁面，**When** 查看主要內容上方，**Then** 同一行依序顯示負責人、狀態、優先級及類型。
2. **Given** 工程師變更任一篩選條件，**When** 篩選值更新，**Then** 該頁結果及已套用條件提示依既有規則更新。
3. **Given** 工程師從一種工作檢視切換至另一種，**When** 開啟目標檢視，**Then** 篩選列仍採相同排列，且既有可跨檢視保留的條件維持不變。

### User Story 2 - 快速辨識並操作篩選條件 (Priority: P1)

工程師可快速分辨不同篩選組，並以滑鼠、鍵盤或輔助科技操作；篩選列不應以大型面板或卡片容器佔用主要版面。

**Why this priority**: 篩選列需同時達成節省空間、清楚分組與可操作性，避免視覺簡化造成辨識或操作問題。

**Independent Test**: 檢視三個頁面及窄視窗下的篩選列，確認篩選分組可辨識、控制項可操作、沒有水平溢出，且沒有大型底層面板。

**Acceptance Scenarios**:

1. **Given** 篩選列顯示於主要版面上方，**When** 工程師掃視各組控制，**Then** 可透過標籤、間距及淡色分隔辨識優先級、類型、狀態與負責人。
2. **Given** 工程師以鍵盤操作篩選列，**When** 焦點移至各控制項，**Then** 焦點可見、選取狀態可辨認且控制項可操作。
3. **Given** 視窗寬度變窄或介面使用英文、日文，**When** 篩選列呈現，**Then** 控制項仍可辨識與操作，且頁面不出現水平溢出。

### Edge Cases

- 優先級、類型或狀態選項較多時，桌面版每組選項仍須維持單行並保持群組邊界清楚；窄版可換行，不得擠壓或遮住其他群組。
- 負責人清單較長或顯示長姓名時，桌面篩選列仍須可操作；可依可用寬度調整控制寬度或在窄版換行，不得產生水平溢出。
- 無篩選結果、載入中或讀取失敗時，篩選列位置及操作方式維持一致，並保留各狀態原有提示。
- Repository 工作區與 All repos 工作區均使用此版面；Repository 固定範圍的既有行為不得被誤認為可變篩選條件。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 列表、看板及甘特 MUST 在主要內容上方提供一致的常用篩選列。
- **FR-002**: 桌面篩選列 MUST 在同一行依序提供負責人、狀態、優先級及類型篩選；狀態、優先級及類型標籤 MUST 各自顯示在「全部」選項左側，且同組選項 MUST 各自保持單行。窄螢幕可依可用寬度換行，但順序 MUST 保持不變。
- **FR-003**: 篩選列 MUST 以緊湊的呈現方式直接置於主要內容上方，不得使用大型底層面板或卡片容器增加不必要空間。
- **FR-004**: 篩選列 MUST 以輕微的間距、標籤或分隔維持群組辨識，不得因視覺簡化而混淆篩選類別。
- **FR-005**: 篩選列 MUST 保留現有篩選值、選取狀態、結果更新、清除、已套用條件提示及適用的跨檢視 URL 狀態行為。
- **FR-006**: 近期已完成篩選開關及各檢視專屬工具 MUST 維持在原有控制位置，不得併入常用篩選列。
- **FR-007**: 所有篩選控制 MUST 支援鍵盤操作、可見焦點及輔助科技可辨識的標籤與選取狀態。
- **FR-008**: 所有支援語系中的標籤及選項 MUST 可辨識；窄螢幕及長標籤下 MUST 不得產生頁面水平溢出或遮蔽控制項。
- **FR-009**: 篩選列版面變更 MUST NOT 改變 Gitea Issue 資料、篩選邏輯、使用者權限或篩選條件的持久化語意。

### Key Entities *(include if feature involves data)*

- **工作檢視常用篩選列**：在列表、看板及甘特主要內容上方共用呈現的優先級、類型、狀態與負責人篩選控制。
- **工作檢視專屬控制**：近期已完成篩選開關，以及依目前檢視而異的排序、日期或其他工具，維持原有位置及行為。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 列表、看板及甘特三種工作檢視中，桌面常用篩選列均以同一行依序呈現負責人、狀態、優先級及類型；後三組標籤各自顯示在「全部」選項左側，所有選項維持單行。
- **SC-002**: 在 1366×768 或更寬的桌面視窗中，常用篩選列無需獨立大型面板即可完整呈現，且主要內容直接位於其下方。
- **SC-003**: 所有現有篩選控制在三種檢視中均可操作，並產生符合既有條件的結果。
- **SC-004**: 窄螢幕及繁體中文、英文、日文介面中，所有篩選控制均可觸及及操作，且頁面沒有水平溢出。
- **SC-005**: 鍵盤操作時，所有篩選控制均有可見焦點；輔助科技可辨識控制標籤與選取狀態。

## Assumptions

- 此版面適用於 All repos 及單一 Repository 中的列表、看板與甘特頁面。
- 優先級、類型及狀態維持既有多選語意；負責人維持既有單選及快捷操作。
- 近期已完成開關與列表排序、看板/甘特工具等檢視專屬控制維持原位置。
- 桌面版將負責人、狀態、優先級及類型放在同一行；窄螢幕可依可用寬度自然換行，但不得隱藏篩選功能或增加水平捲動需求。
