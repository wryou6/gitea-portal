# Feature Specification: Gitea 使用者大頭貼與姓名顯示

**Feature Branch**: `main`（本次未建立新分支）

**Created**: 2026-10-02

**Status**: Draft

**Input**: User description: "把 Gitea 使用者大頭貼顯示到 Portal，包含右上角帳戶及 Issue 人員；如果有設定名字就優先顯示。一般畫面以姓名為主、帳號輔助，人員下拉選單顯示姓名（帳號）；重新載入頁面時更新登入者資料，Issue 人員隨 Issue 資料更新。"

## Clarifications

### Session 2026-10-02

- Q: Gitea 大頭貼要顯示在哪些位置？ → A: 右上角帳戶，以及 Issue 清單、Kanban、Gantt、詳情與留言中的人員。
- Q: 有設定姓名時，帳號要怎麼呈現，方便辨識同名的人？ → A: 一般畫面顯示姓名，提示中提供帳號；人員下拉選單顯示「姓名（帳號）」。
- Q: 在 Gitea 改名字或頭貼後，Portal 要何時取得新資料？ → A: 重新載入頁面時更新登入者資料；Issue 人員隨 Issue 資料重新取得。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 辨識目前登入帳戶 (Priority: P1)

工程師登入 Portal 後，可以透過右上角的大頭貼及姓名辨識目前帳戶；未設定姓名時仍可透過帳號辨識自己，並繼續使用帳戶選單。

**Why this priority**: 帳戶是所有工作頁面的共同入口，清楚辨識目前身份可避免在共用工作站使用錯誤帳戶。

**Independent Test**: 分別以有姓名、未設定姓名及沒有可載入頭貼的使用者登入，確認右上角資訊與 Gitea 一致，帳戶選單、設定與登出仍可操作。

**Acceptance Scenarios**:

1. **Given** 登入者在 Gitea 已設定姓名及可載入的大頭貼，**When** 登入者開啟 Portal，**Then** 右上角顯示該頭貼及姓名，並可取得其帳號。
2. **Given** 登入者未設定姓名或姓名只有空白，**When** 登入者開啟 Portal，**Then** 右上角顯示登入帳號。
3. **Given** 登入者未提供頭貼或圖片載入失敗，**When** Portal 呈現帳戶，**Then** 顯示預設人像及姓名或帳號，不呈現破圖。
4. **Given** 登入者使用滑鼠或鍵盤操作帳戶選單，**When** 選擇設定或登出，**Then** 原有操作仍正常，且可辨識目前帳戶。

---

### User Story 2 - 在工作檢視辨識 Issue 人員 (Priority: P1)

工程師在跨 Repository 或單一 Repository 的 Issue 清單、Kanban、Gantt、詳情及留言中，能透過相同的頭貼與姓名呈現方式辨識建立者、負責人及留言者。

**Why this priority**: Issue 的日常閱讀與交接需要辨識人員，統一顯示可減少只看帳號造成的辨識負擔。

**Independent Test**: 查看同一筆含建立者、多位指派人及留言的 Issue，確認各工作區與視圖的人員資訊一致，且每個姓名及頭貼均對應正確帳號。

**Acceptance Scenarios**:

1. **Given** 使用者查看 Issue 清單或 Gantt，**When** 負責人或建立者欄位顯示，**Then** 有設定姓名的人員顯示頭貼與姓名，未設定姓名的人員顯示頭貼與帳號。
2. **Given** 使用者查看 Kanban，**When** 卡片顯示目前負責人或最後負責人，**Then** 頭貼與姓名對應原有規則選取的帳號，不改變人員選取或完成狀態語意。
3. **Given** 使用者開啟 Issue 詳情，**When** 查看建立者、目前負責人、指派人清單及留言，**Then** 所有人員均依相同規則呈現，且指派人順序維持 Gitea 提供的順序。
4. **Given** Issue 沒有負責人或沒有留言，**When** 使用者查看相關區域，**Then** 維持既有未指派或無留言提示，不建立虛構人員。
5. **Given** 使用者查看長姓名或多位人員，**When** 瀏覽表格、卡片或窄視窗，**Then** 頭貼與文字不遮住相鄰內容，完整姓名及帳號仍可取得，Gantt 表頭與列保持對齊。

---

### User Story 3 - 選取正確的人員 (Priority: P1)

工程師在篩選或指派人員時，優先依姓名辨識候選人，同時能透過帳號區分同名使用者，並確保操作套用到選取的帳戶。

**Why this priority**: 姓名可能重複，顯示姓名不應導致錯誤篩選或交接。

**Independent Test**: 使用兩個姓名相同、帳號不同的人員進行篩選及指派，確認選項可區分，結果與操作對象均對應選取的帳號。

**Acceptance Scenarios**:

1. **Given** 人員下拉選單中的候選人有姓名，**When** 使用者開啟選單，**Then** 選項顯示「姓名（帳號）」；未設定姓名的候選人只顯示帳號。
2. **Given** 兩位人員姓名相同，**When** 使用者取得畫面上的人員提示或操作下拉選單，**Then** 可以辨識兩人的不同帳號。
3. **Given** 使用者依姓名選擇一位負責人，**When** 套用篩選或確認指派，**Then** 使用選取人員的帳號完成操作，不以姓名匹配其他人。
4. **Given** 使用者套用人員篩選，**When** 查看已套用的篩選條件，**Then** 有姓名時優先顯示姓名，且仍可辨識對應帳號。

---

### User Story 4 - 取得更新後的姓名與頭貼 (Priority: P2)

工程師在 Gitea 修改姓名或大頭貼後，重新載入 Portal 即可更新登入者資訊；重新取得 Issue 資料時，相關人員資訊一併更新。

**Why this priority**: Gitea 是使用者資料來源，Portal 應反映更新，並在外觀資料暫時不可用時保留可辨識的工作畫面。

**Independent Test**: 在 Gitea 更新姓名及大頭貼後，重新載入 Portal 並重新取得 Issue 資料；另模擬外觀資料暫時無法更新與登入授權失效，確認兩者處理不同。

**Acceptance Scenarios**:

1. **Given** 登入者已在 Gitea 更新姓名或大頭貼且資料可讀取，**When** 重新載入 Portal，**Then** 右上角顯示更新後資料，不需要先登出再登入。
2. **Given** Issue 人員已在 Gitea 更新姓名或大頭貼且資料可讀取，**When** Portal 重新取得該 Issue 或留言，**Then** 對應人員顯示更新後資料。
3. **Given** 登入授權仍有效但外觀資料暫時無法更新，**When** 使用者重新載入 Portal，**Then** 使用已取得的姓名與頭貼資料，或帳號與預設人像，不因外觀資料失敗而要求重新登入。
4. **Given** 登入授權明確失效，**When** 使用者重新載入或繼續存取受保護工作資料，**Then** Portal 進入既有重新登入流程，不以外觀資料降級維持受保護存取。

---

### Edge Cases

- 姓名缺失、空字串或只有空白時，顯示帳號；有效姓名去除前後空白後顯示。
- 多位使用者姓名相同時，仍以各自帳號辨識，不合併頭貼或人員資料。
- 頭貼資料缺失、圖片拒絕存取、網路中斷或瀏覽器無法載入圖片時，顯示預設人像，不影響姓名文字與操作。
- 既有登入階段或工作資料缺少姓名與頭貼時，仍可顯示帳號與預設人像。
- 切換登入帳戶後，不得沿用前一帳戶的登入者姓名或頭貼。
- Issue 只有單一負責人資料、完整指派清單含多位人員，或已完成而沒有目前負責人時，仍依既有人員選取規則呈現，不以外觀資料猜測負責人。
- 外觀資料降級不適用於必要的 Repository、Issue 或留言讀取失敗；必要資料查詢失敗時維持既有錯誤處理，不把部分工作資料呈現為完整結果。
- 長姓名、非拉丁文字及窄視窗下，保持頭貼與文字可辨識；圖片載入或失敗前後保留相同空間，避免表格與卡片跳動。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Portal MUST 以 Gitea 提供的使用者姓名與大頭貼作為顯示來源，不建立另一份可獨立編輯的使用者資料。
- **FR-002**: Portal MUST 優先顯示去除前後空白後的 Gitea 姓名；姓名缺失或去除空白後為空時，MUST 顯示登入帳號。
- **FR-003**: Portal MUST 在右上角帳戶與範圍內的 Issue 人員旁顯示對應大頭貼；頭貼缺失或無法載入時，MUST 顯示預設人像並保留人員文字。
- **FR-004**: Issue 人員顯示 MUST 涵蓋 All repos 與單一 Repository 的 Issue 清單、Kanban、Gantt、詳情及留言。Issue 詳情 MUST 顯示建立者、目前負責人與指派人清單。
- **FR-005**: 一般畫面 MUST 以姓名或帳號作為主要文字，並透過輔助提示提供帳號；有姓名的人員下拉選單 MUST 顯示「姓名（帳號）」，未設定姓名時只顯示帳號。
- **FR-006**: 人員身份、篩選、指派、權限及個人偏好 MUST 以帳號辨識，不得以姓名代替帳號。相同姓名的帳戶 MUST 保持可區分。
- **FR-007**: 人員篩選的選項與已套用條件 MUST 優先顯示姓名，並維持原有帳號篩選值與連結語意。
- **FR-008**: Portal MUST 維持目前負責人、最後負責人及指派人順序的既有規則；無人員時 MUST 保留既有空狀態文案，不建立虛構姓名或頭貼。
- **FR-009**: 重新載入 Portal 時，登入者姓名與頭貼 MUST 嘗試取得最新 Gitea 資料；Issue 及留言人員資訊 MUST 隨相應工作資料重新取得而更新，不要求使用者逐人查詢或重新登入。
- **FR-010**: 外觀資料暫時無法更新時，Portal MUST 使用已取得資料或帳號與預設人像維持人員辨識；此降級 MUST 不改變登入授權失效或必要工作資料讀取失敗的處理。
- **FR-011**: 新增的人員顯示 MUST 遵守目前 Gitea 使用者權限，不得以較高權限身份取得額外使用者或工作資料，亦不得將 credentials 暴露於畫面或日誌。
- **FR-012**: 顯示姓名與頭貼 MUST 不修改 Gitea 使用者、Issue、留言、Labels、狀態或排程資料，且 MUST 不新增 Portal 使用者或 Issue 的持久副本。
- **FR-013**: 帳戶選單、設定、登出、人員篩選、指派及 Kanban 拖曳 MUST 維持可操作；repair annotation、錯誤與 anomaly 區域 MUST 保持可辨識。
- **FR-014**: 頭貼與文字 MUST 在明暗主題及窄視窗下保持可讀，不遮住相鄰內容；Gantt 欄位與表頭 MUST 對齊，圖片載入前後 MUST 不造成頭貼區域大小變動。
- **FR-015**: 人員身份及輔助帳號提示 MUST 可由滑鼠、鍵盤與輔助科技取得；頭貼旁已有相同身份文字時 MUST 避免重複朗讀，帳戶選單 MUST 保留可理解的操作名稱。
- **FR-016**: 新增或修改的介面文案、提示及無障礙名稱 MUST 支援繁體中文、英文與日文；Gitea 姓名與帳號 MUST 保留原文字，不作翻譯。
- **FR-017**: 缺少新增外觀資料的既有登入階段與工作資料 MUST 仍可顯示並操作，切換帳戶後 MUST 顯示新帳戶資訊。

### Key Entities *(include if feature involves data)*

- **使用者身份**：由唯一登入帳號辨識的 Gitea 使用者；姓名可重複，也可能未設定。
- **使用者外觀資料**：Gitea 提供的姓名與大頭貼；用於閱讀與辨識，不作為身份或權限判斷依據。
- **Issue 人員角色**：Issue 建立者、目前或最後負責人、有序指派人清單與留言者；各角色關聯至使用者身份。
- **登入者資訊**：目前 Portal 登入帳戶的身份及已取得外觀資料；重新載入時更新，不跨帳戶沿用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在右上角帳戶與所有範圍內的 Issue 人員位置，有姓名、無姓名、空白姓名三類情境的主要文字均 100% 符合姓名優先及帳號 fallback 規則。
- **SC-002**: 所有範圍內的人員在頭貼正常、缺失與載入失敗三類情境下，均顯示正確頭貼或預設人像；破圖數為零。
- **SC-003**: 使用兩位姓名相同、帳號不同的人員驗收時，所有人員選項與提示均可區分帳號，篩選及指派結果 100% 對應使用者選取的帳戶。
- **SC-004**: Gitea 最新資料可讀取時，登入者姓名及頭貼在一次 Portal 頁面重新載入後更新；Issue 及留言人員在一次相應資料重新取得後更新。
- **SC-005**: 外觀資料暫時不可用、登入授權失效及必要工作資料讀取失敗三類情境均依各自規則處理，外觀資料失敗引發的不必要重新登入次數為零。
- **SC-006**: 在繁體中文、英文及日文的明暗主題下，桌面與窄視窗驗收均無人員內容遮住相鄰欄位，Gantt 表頭與列對齊；鍵盤及輔助科技可取得姓名與帳號。
- **SC-007**: 驗收姓名及頭貼顯示與重新載入時，新增的 Gitea 寫入次數為零；帳戶選單、登出、篩選、指派與 Kanban 拖曳仍完成原有操作。

## Assumptions

- 本功能服務已登入且具有相應工作資料讀取權限的內網工程團隊，不新增使用者角色或權限。
- Gitea 維持姓名與頭貼的管理入口；Portal 不提供姓名編輯、頭貼上傳或另一套使用者目錄。
- 頭貼顯示依賴使用者瀏覽器能載入 Gitea 提供的圖片；無法載入時使用預設人像，不建立 Portal 圖片儲存庫。
- 人員下拉選單保持文字選項；本次不要求在選單選項內顯示頭貼，也不改造接受帳號文字輸入的建立或編輯欄位。
- 本次不新增原本沒有的人員欄位或卡片內容，唯 Issue 詳情補上建立者；設定頁現有帳戶辨識文字亦採姓名優先並保留帳號輔助資訊。
- 人員排序沿用既有帳號排序規則；姓名優先只改變人員顯示，不改變已保存排序或篩選偏好。
- 外觀資料只隨頁面或相應工作資料重新取得而更新，不要求背景即時推送；暫時失敗時可沿用目前登入階段已取得的資料。
- 桌面驗收採 1440 CSS 像素寬，窄視窗採 375 與 720 CSS 像素寬；既有工作圖表可保留必要的水平捲動，但不得有人員內容重疊或無法取得完整身份資訊。
