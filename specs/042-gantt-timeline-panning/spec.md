# Feature Specification: Gantt 時間軸拖曳平移

**Feature Branch**: `042-gantt-timeline-panning`

**Created**: 2026-10-12

**Status**: Draft

**Input**: User description: Gantt 檢視底部目前有兩個水平捲動控制，保留一個；使用者也希望能在時間軸空白處拖曳水平捲動。

## Clarifications

### Session 2026-10-12

- Q: 在窄螢幕觸控裝置上，時間軸空白處是否也要支援以手指拖曳平移？ → A: 觸控裝置空白處可平移；未排程列仍可拖曳建立排程。
- Q: 在 390px 手機寬度下，固定欄位遮住日期格時，手指應如何開始平移時間軸？ → A: 允許從非互動欄位空白處拖曳；連結、按鈕與未排程建立區仍保留原操作。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用單一捲軸瀏覽時間軸 (Priority: P1)

工程師在 Gantt 中查看超出可視範圍的日期時，只需面對一個水平捲動控制，並能直接在時間軸空白處按住拖曳來移動畫面。

**Why this priority**: 重複的水平控制造成操作混淆；在圖表上直接拖曳也能讓長時間軸更容易瀏覽。

**Independent Test**: 開啟含有多個日期區間的 Gantt，確認底部只顯示一個水平捲軸；拖曳空白時間軸後，日期標頭與列內容同步水平移動。

**Acceptance Scenarios**:

1. **Given** 時間軸寬於可視區域，**When** 使用者查看 Gantt 底部，**Then** 只顯示圖表的原生水平捲軸，且可用鍵盤操作。
2. **Given** 時間軸存在可見空白日期格，**When** 使用者在空白處按住並水平拖曳，**Then** 時間軸依拖曳方向移動，日期標頭與 Issue 列保持對齊。
3. **Given** 使用者從 Issue bar、連結、按鈕或其他可操作控制開始操作，**When** 使用者拖曳或點擊，**Then** 原有操作仍正常執行，不會被時間軸平移攔截。
4. **Given** 使用者以觸控裝置操作可平移的空白時間軸區域，**When** 使用者以手指水平拖曳，**Then** 時間軸水平平移，未排程 Issue 列仍保留既有建立排程手勢。
5. **Given** 390px 窄螢幕上的固定欄位遮住日期格，**When** 使用者從非互動欄位的空白處以手指水平拖曳，**Then** 時間軸水平平移；連結、按鈕與未排程建立區仍執行各自原有操作。

### User Story 2 - 保留未排程 Issue 的排程建立操作 (Priority: P1)

工程師在未排程 Issue 的時間軸列上拖曳日期範圍，仍可建立該 Issue 的排程；時間軸平移不得意外修改 Issue 排程。

**Why this priority**: 排程建立是既有操作，新增平移手勢不能改變其資料結果。

**Independent Test**: 在含有未排程 Issue 的 Gantt 中拖曳其空白時間軸列，確認建立日期區間操作維持原樣；在其他空白時間軸區域拖曳則只移動畫面。

**Acceptance Scenarios**:

1. **Given** 未排程 Issue 的日期格，**When** 使用者拖曳一段日期範圍，**Then** 既有建立排程流程照常執行。
2. **Given** 任一可平移的空白時間軸區域，**When** 使用者拖曳，**Then** 只改變目前瀏覽位置，不寫入或修改 Issue 資料。

### Edge Cases

- 時間軸已在最左或最右端時，拖曳不應把捲動位置移出有效範圍。
- 沒有已排程 Issue 時，仍保留目前的空時間軸呈現與可用捲動控制；空白區拖曳只用於瀏覽。
- 觸控裝置在未排程 Issue 列上拖曳時，仍執行建立排程；在其他空白區拖曳時執行平移。
- 窄螢幕上的固定欄位遮住日期格時，觸控平移可從非互動欄位空白處開始；互動控制及未排程建立區不觸發平移。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Gantt MUST 以圖表原生水平捲動容器作為唯一水平瀏覽方式，MUST NOT 顯示自訂 range slider；內容超出可視範圍時，MUST 顯示一個原生水平捲軸，且捲動方式須可由鍵盤操作。
- **FR-002**: 使用者 MUST 能從可平移的時間軸空白區按住並水平拖曳以移動畫面；日期標頭與 Issue 列 MUST 同步移動並保持對齊。窄螢幕固定欄位遮住日期格時，觸控使用者 MUST 能從非互動欄位空白處開始平移。
- **FR-003**: 平移手勢 MUST 不攔截 Issue bar、連結、按鈕或其他既有互動控制的操作。
- **FR-004**: 未排程 Issue 列的拖曳建立日期區間操作 MUST 維持原有行為；時間軸平移本身 MUST NOT 修改 Issue 或其排程資料。
- **FR-005**: 時間軸到達可瀏覽範圍邊界時 MUST 保持在有效捲動範圍；無排程 Issue 時 MUST 保留相同圖表捲動容器，並在內容超出可視範圍時可水平瀏覽。
- **FR-006**: 空白區平移 MUST 支援滑鼠、觸控筆與手指；觸控手勢 MUST 依拖曳開始位置保留未排程列的建立排程操作，且不得攔截連結、按鈕或其他互動控制；窄螢幕固定欄位遮住日期格時，非互動欄位空白處 MUST 可用於觸控平移。

### Key Entities

- **Gantt 檢視位置**：使用者目前瀏覽的水平日期位置；只影響畫面呈現，不是 Issue 資料。
- **Issue 排程**：既有 Gitea 開始日與到期日；本功能不改變其來源或寫入行為。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 當 Gantt 內容超出可視範圍時，底部顯示一個原生水平捲軸且不顯示自訂 range slider；未超出時不顯示多餘捲動控制。
- **SC-002**: 在時間軸空白處拖曳後，日期標頭及 Issue 列在同一水平位置呈現，且不產生排程資料變更。
- **SC-003**: 未排程 Issue 列的拖曳建立排程仍可完成，且其他既有 bar、連結及控制操作不受平移手勢影響。
- **SC-004**: 在桌面及窄螢幕版面皆可用滑鼠或觸控平移瀏覽時間軸，並可用鍵盤操作唯一捲動控制。

## Assumptions

- 保留圖表本身的原生水平捲軸，移除其下方重複的自訂滑桿。
- 未排程 Issue 列保留現有拖曳建立日期區間手勢；平移僅作用於其他空白時間軸區域。
- Gitea 仍是 Issue 與排程資料唯一來源；本功能只改變 Gantt 的檢視互動。
